## 更新规则

1. 先保留原始 Issue 与证据，再更新本台账；台账不能替代原始反馈。
2. 每次分级或改级都写明依据，不能只写优先级标签。
3. 修复 P0 / P1 时关联提交、验证结果和目标用户复验结论。
4. 关闭 Issue 前记录“已修复、已接受、重复、无法复现或不采纳”的具体理由。
5. 每次做 `v0.1.0` / `rc.2` 判断前，重新审计全部开放 Issue 与本表。
