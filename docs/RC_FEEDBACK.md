# v0.1.0-rc.1 试用与反馈指南

> - 适用版本：`v0.1.0-rc.1`
> - 在线体验：https://a7m0sphere.github.io/chem3D-learn/
> - Release：https://github.com/A7m0spHere/chem3D-learn/releases/tag/v0.1.0-rc.1
> - 当前状态：Release Candidate / Prerelease，不是稳定版。

## 目标

这轮试用要回答三个问题：

1. 普通学生和教师能否在真实设备上进入并完成核心学习任务？
2. 3D 结构、教学结论和操作反馈是否准确、清楚且不误导？
3. 是否存在必须在 `v0.1.0` 前修复的 P0 / P1 问题？

反馈入口已经建立不代表 RC 已通过真实用户验证。只有实际试用记录才能进入反馈台账；没有 Issue 也不能自动推导为“没有问题”。

## 建议试用角色

- **学生**：首次接触某一空间结构，能否只凭页面提示完成观察并归纳结论。
- **化学教师**：课堂投影时，模型、标签、讲解和控件是否足够清楚，是否有教学误导。
- **不同设备使用者**：在桌面、平板、手机和不同 Chromium / Safari 浏览器中检查兼容性。
- **键盘或辅助技术使用者**：检查主要导航、工具栏和结果播报是否可理解、可操作。

请记录真实角色即可，不收集姓名、学校、班级、联系方式或其他个人信息。

## 建议测试路径

| 范围 | 建议操作 | 应观察的结果 |
| --- | --- | --- |
| 站点与路由 | 打开首页、Modules、Paths、Exam、About；再直接打开一个深层模块 URL | 页面可进入，地址不丢失，无空白页或持续报错 |
| 核心分子 | 依次观察 CH₄、NH₃、H₂O、CO₂、BF₃，旋转 / 缩放并切换可用的角度、孤对电子、标签和步骤 | 3D 画布稳定；构型、键角、孤对电子和极性表述不互相矛盾 |
| NaCl 教学模式 | 切换晶胞、六配位、计数等教学步骤 | 离子、图例和讲解一致；配位虚线不会被误解为共价键 |
| NaCl 周期探索 | 切换 1×1×1、2×2×2、3×3×3，切换边框；选择中心或边界显示副本，观察 6 个异号最近邻、ghost 与隔离 / 退出选择 | 数量与身份说明清楚；边界选择可用；没有异常长线、错误配位或 Canvas 崩溃 |
| 有机拼装 | 拖入原子或常用片段，尝试吸附、拆下、撤销 / 重做；观察分子式、价态、官能团、键角和命名反馈 | 操作有反馈；超出支持范围时明确拒绝猜测，不给出伪精确名称 |
| 响应式与课堂 | 在约 390px 手机宽度、常用桌面宽度和课堂投影环境浏览核心页面 | 无横向溢出；核心文字、按钮和 3D 画布不被裁切或遮挡 |
| 可访问性 | 仅用键盘浏览主要页面和工具栏；如适用，开启读屏、页面缩放或减少动态效果 | 焦点可见，控件名称和状态可理解，关键结果不只依赖颜色 |

不要求每位试用者覆盖全部路径。请优先记录真实使用中遇到的问题，不要为了填满台账制造反馈。

## 如何提交

前往 [GitHub Issues 新建入口](https://github.com/A7m0spHere/chem3D-learn/issues/new/choose)，选择最匹配的表单：

- **Bug 报告**：页面不可用、Canvas 黑屏、稳定报错、交互失败或浏览器兼容问题。
- **化学内容反馈**：结构、术语、计数、标注或教学结论可能不准确或容易误导。
- **体验与可访问性反馈**：操作摩擦、布局、移动端、课堂投影、键盘 / 读屏或非核心性能问题。

一条 Issue 尽量只描述一个可复现问题。请附页面 / 模块、步骤、实际与预期结果、设备与浏览器版本、发生频率，以及去除敏感信息后的截图或错误信息。维护者会在复现后统一判定优先级；提交者不需要自己决定 P0–P3。

安全问题不要公开披露利用步骤、密钥或敏感数据。当前仓库未启用 GitHub 私密漏洞报告；请先通过你与维护者已有的私下渠道联系。若没有私下渠道，只能公开提交不含漏洞细节的联络请求。

## 分诊流程

1. **确认来源**：记录 Issue、真实试用场景、版本和环境。
2. **检查重复**：关联已有 Issue，但保留新增环境或复现证据。
3. **尝试复现**：区分稳定复现、偶发、信息不足和无法复现。
4. **核对事实**：化学问题优先查教材、课程标准、IUCr、同行评审论文或可追溯数据库；项目测试不能充当化学来源。
5. **判定 P0–P3**：依据影响范围、教学风险和复现证据，不按措辞强烈程度排序。
6. **写入台账**：只记录真实反馈与处置，不创建示例反馈。
7. **决定版本路径**：P0 / P1 修复后重新验证；P2 明确修复或接受；P3 可后续处理。

## P0–P3 优先级

| 级别 | 定义 | 典型情况 | RC 处理 |
| --- | --- | --- | --- |
| **P0 发布阻断** | 线上核心体验不可用，或存在高风险事实 / 安全问题 | 页面不可达；广泛 WebGL 黑屏；数据丢失或安全问题；核心化学结论错误；主流浏览器完全不可用 | 立即停止稳定版判断；先复现、修复并完成发布级回归 |
| **P1 必须发布 rc.2** | 核心功能在明确环境中稳定失败，或教学 / 布局问题严重影响使用 | 核心功能稳定失败；NaCl 选择、配位或计数错误；主要设备严重布局破坏；教学表述明显误导；有效深层路由无法恢复 | 修复生产代码或核心内容，发布并重新试用 `rc.2` |
| **P2 建议稳定版前处理** | 不阻断核心任务，但有可复现的局部质量问题 | 局部交互摩擦；少量视觉重叠；轻微移动布局；可访问性缺口；非核心性能问题 | 稳定版前修复，或记录证据、影响和接受理由 |
| **P3 后续改进** | 不属于 RC 正确性与可用性门槛 | 新功能设想；样式偏好；非核心动画；扩展内容；重构建议 | 进入后续 backlog，不因 P3 单独制造新 RC |

优先级可以在新证据出现后调整。单次主观不喜欢通常是 P3；能够稳定阻断核心学习任务的同一表现可能是 P1。化学核心结论错误即使只在一个模块出现，也可能是 P0。

## 版本决策门槛

### 只有同时满足以下条件，才可以考虑发布 v0.1.0

- 已有真实学生、教师或目标设备使用者完成候选版本试用，并留下可审计记录。
- 没有未关闭的 P0 / P1。
- 所有已知 P2 已修复，或已有明确的影响评估、接受理由和后续处理记录。
- `main` 通过发布范围内的完整自动化验证。
- 对应 `main` 提交的 GitHub Pages build / deploy 与线上冒烟通过。
- 没有未解决的化学内容发布阻断项。

满足门槛只代表“可以做稳定版决策”，不等于自动创建 `v0.1.0`。版本号、tag 和 Release 仍需单独授权与发布任务。

### 出现以下任一情况，应发布 rc.2，而不是继续沿用 rc.1

- P0 / P1 导致生产代码、核心交互或核心教学内容发生变化。
- 修复改变逻辑测试契约或视觉快照。
- 修复需要目标用户在真实场景中重新验证。

`rc.2` 必须从完成修复和全套验收的新提交发布，不修改、移动或重建 `v0.1.0-rc.1`。

### 以下情况继续保留 rc.1

- 真实反馈数量仍不足，无法做稳定版判断。
- 只有 P3 建议，或尚无证据证明需要修改候选版本。
- 没有必要的产品变化，仅为了“看起来有进度”而改版本号。

当前结论：反馈入口和分级流程已经建立，但尚无真实反馈；继续保留 `v0.1.0-rc.1`，不发布 `rc.2`，也不开始发布 `v0.1.0`。
